# Veridict AI

Veridict AI is an advanced, multi-layered security analysis engine designed to detect phishing links, malicious emails, and smishing (SMS phishing) attempts in real-time. By combining traditional cybersecurity heuristics, live reputation APIs, and an AI-driven analytical model, Veridict AI provides a comprehensive risk assessment for any text or URL to keep end-users safe from scams.

##  Introduction

The application exposes a robust parsing and extraction pipeline capable of dissecting simple URLs or entire email/SMS bodies. It evaluates the fundamental structure of the message, tests internet registries, and applies semantic understanding to determine the exact intent behind the message.

The system evaluates submitted data on three distinct fronts (Rules, Reputation, and AI), computing a final weighted **Risk Score** (from 0% to 100%) and a **Risk Level** (Secure, Suspicious, or Dangerous).

---

## How We Determine if a Link or Text is Secure

When a message or URL is submitted to the API, it undergoes the following extraction and evaluation journey:

### 1. Feature Extraction
The parsing module strips out any actionable data from the text:
*   **URLs & Domains:** Identifies root domains, safely resolving subdomains and stripping protocol clutter (e.g., `www.`).
*   **Keywords:** Scans for urgency markers, financial requests, or security alert vocabulary.

### 2. The Three-Pillar Scoring System

The extracted data is evaluated by three independent engines. The final Risk Score is a weighted average of these three pillars: **Final Score = (Rule Score × 0.35) + (Reputation Score × 0.35) + (AI Score × 0.30)**.

#### Pillar A: Rule Engine (35% Weight)
The Rule Engine acts as our first line of defense, utilizing deterministic logic to catch common scam patterns:
*   **Suspicious TLDs:** Penalizes domains ending in high-risk extensions (e.g., `.run`, `.online`, `.vip`).
*   **URL Shorteners:** Flags heavily abused shorteners (e.g., `bit.ly`, `t.co`) which mask the true destination.
*   **Typosquatting:** Cross-references the domain against a static list of highly-abused brands (e.g., detecting `netflxi` instead of `netflix`).
*   **Text Heuristics:** Increases risk if the message is unusually short and contains a link, or uses a high density of urgent/social engineering keywords.

#### Pillar B: Reputation Service (35% Weight)
The Reputation Service performs live interrogations over the internet:
*   **Google Safe Browsing V4:** Cross-references URLs against Google's live Threat Database (Malware & Social Engineering). If flagged by Google, the system triggers a **Critical Override**, immediately maxing the final score to 100% (Dangerous).
*   **DNS Resolution (Socket Ping):** Checks if the domain actually resolves to a valid IP. Fake, randomly generated domains that do not resolve trigger a heavy risk penalty.
*   **WHOIS Age Verification:** Queries global registrars for the domain's creation date. Fresh domains (under 30 days old) are treated as highly suspicious.
*   **Well-Known Entity Bypass:** Globally recognized root domains and official government TLDs (e.g., `.gov.pt`, `.edu`) bypass WHOIS extraction, securing a 0% risk addition on this pillar to prevent false positives.

####  Pillar C: AI Engine (30% Weight)
Using a Large Language Model (LLM) backed by a ChromaDB RAG (Retrieval-Augmented Generation) instance:
*   The AI reviews the raw text alongside the technical flags generated by the Rule and Reputation engines.
*   It analyzes the semantic context (e.g., "Is this a legitimate banking notification or an extortion attempt?").
*   It assigns a contextual score and generates a concise, bulleted explanation (in English) outlining exactly why it took its decision, alongside actionable recommendations for the user.

##  Final Risk Levels

Based on the final computed score (after checking for critical overrides like an active Google Threat or unresolved DNS), the system classifies the input as:

*   🟢 **Secure (0% - 34%):** The text or link exhibits standard communication patterns, uses reputable domains, and raises no red flags across registries.
*   🟡 **Suspicious (35% - 69%):** The input contains some risky traits (e.g., an unusual TLD, hidden WHOIS data, or urgent language). Users should validate cautiously before clicking.
*   🔴 **Dangerous (70% - 100%):** Confirmed threat. The domain is blacklisted, actively flagged by Google Safe Browsing, clearly typosquatting, or exhibits severe phishing characteristics. Do not interact.
